# 扫雷游戏

基于 C 语言 + EasyX 图形库实现的扫雷小游戏，支持左右键交互、右键插旗、胜负判定与贴图渲染。

## 项目功能

- 地图渲染：格子贴图、地雷隐藏与揭示
- 交互操作：左键翻开、右键插旗/取消插旗
- 游戏判定：踩雷失败、全部排雷胜利（弹窗提示）

## 问题清单

| 1 | 程序随机崩溃 | 内存安全 |

## 问题一：程序随机崩溃

**【问题】**：无编译报错，程序运行过程随机崩溃退出。

**【排查与原因】**：遍历地雷周边格子时缺少边界判断，数组下标出现负数，发生数组越界、非法内存访问；数组越界属于运行期错误，编译器无法提前检查。

**【解决方案】**：数组访问处增加边界校验，数组下标必须在合法范围再执行读写，杜绝下标负数、越界访问。

**【经验总结】**：数组越界不一定会产生编译报错，属于运行时内存错误；访问数组前务必校验下标合法性。

## 问题二：EasyX 图形库编译失败

**【问题】**：VSCode + MinGW 环境编译报 `fatal error: graphics.h: No such file or directory`，找不到 EasyX 头文件；手动复制头文件、添加 `-I/-L` 参数依旧无法正常编译，`.c` 文件无法编译库中 C++ 特性代码。

**【排查与原因】**：EasyX 官方库面向 MSVC（Visual Studio），并不原生支持 MinGW；头文件、库路径配置错误，同时混淆 gcc/g++ 编译器，`.c` 源码无法编译库内 C++ 特性代码。

**【解决方案】**：放弃 MinGW + VSCode 环境，切换至 Visual Studio 2022，安装官方 EasyX 包，规避 MinGW 移植带来的兼容性问题。

**【经验总结】**：第三方图形库需要和编译器严格匹配，环境配置问题会消耗大量开发时间，工具选型十分重要；要分清编译阶段与链接阶段的不同错误。

## 问题三：弹窗画面闪烁

**【问题】**：游戏胜利或踩雷失败弹出 MessageBox 弹窗时，EasyX 图形窗口画面持续闪烁，弹窗与游戏窗口互相抢占焦点。

**【排查与原因】**：弹窗写在游戏绘图主循环内部，MessageBox 阻塞时游戏循环仍持续调用 DrawMap 重绘画面；未开启双缓冲，`cleardevice()` 直接刷新屏幕，引发画面频闪。

**【解决方案】**

1. 使用 EasyX 双缓冲接口 `BeginBatchDraw()`、`EndBatchDraw()`，绘图先写入内存缓冲区再一次性输出屏幕；增加 `Sleep(10)` 限制帧率，减少无效重绘。
2. 将胜利、失败弹窗移出游戏绘图循环，游戏结束先跳出刷新循环，画面静止后再弹出提示框，消除弹窗阶段持续重绘。

**【经验总结】**：GUI 程序不能将阻塞式弹窗放在渲染循环内部，弹窗阻塞线程但不会终止循环，极易造成画面闪烁异常；大量贴图、清屏的图形程序必须使用双缓冲机制，避免直接逐帧输出屏幕带来的画面闪烁。

## 问题四：开局地雷直接显示

**【问题】**：游戏刚启动未做任何操作，地图地雷贴图直接显示，地雷完全暴露，游戏逻辑失效。

**【排查与原因】**：渲染分支逻辑错误，原生地雷标记 -1 直接渲染地雷贴图；没有区分"游戏进行中的地雷"和"游戏结束展示地雷"两种状态。

**【解决方案】**：新增地雷状态标记：正常游戏地雷值为 -1，踩雷后全部地雷修改为 -10；调整 DrawMap 渲染分支优先级，仅值等于 -10 才绘制地雷贴图；正常游戏时 -1 渲染未翻开遮挡方块，隐藏地雷。

**【经验总结】**：同一游戏对象存在多种展示状态时，应当设置独立状态标记区分业务逻辑，不要直接使用原始业务值控制渲染。

## 问题五：Windows 类型与宏编译报错

**【问题】**：未引入 windows.h 时，`HWND`、`MessageBox`、鼠标消息相关宏报编译未定义错误。

**【排查与原因】**：`HWND`、弹窗、鼠标消息宏依赖 windows.h 头文件，代码没有引入该头文件。

**【解决方案】**：添加头文件 `#include <windows.h>`，补齐窗口、弹窗、鼠标消息的编译依赖。

**【经验总结】**：使用 Windows 系统 API 时，要确认引入对应的头文件，防止类型、宏未定义的编译错误。

---

## 问题六：右键插旗功能异常

**【问题】**：隐藏的地雷格子上右键无法插上旗子；无雷的空白格子可以插旗，但是无法取消旗子；旗子会覆盖已经翻开显示数字的格子。

**【排查与原因】**

1. DrawMap状态判断逻辑不完善，旗子状态切换逻辑存在漏洞，导致插旗不显示；
2. 没有对未翻开（`val >= 0 && val <= 8`）的格子做拦截校验，可以随便插旗，但不能取消。

**【解决方案】**

1. 允许原始地雷 `val == -1` 和普通未开格子执行插旗操作；
2. 修改状态切换逻辑：如果当前已经是旗子状态（`val >= 20`）则减去 20 取消旗子，否则加上 20 挂上旗子，实现旗子可挂可取消。

**【经验总结】**：交互功能要完整覆盖全部格子状态：已翻开格子、普通未开格子、地雷格子、已插旗格子，每种状态都要考虑允许/禁止的操作，避免出现部分格子交互失效、状态无法回退的 bug。
