# 贪吃蛇游戏

基于 JavaScript 语言实现的贪吃蛇小游戏，支持方向键操控、食物进食、蛇身增长、得分与计时，含游戏结束与 R 键重置功能。

## 项目功能

- 蛇的移动与增长：方向键控制、吃食物变长
- 食物刷新：随机位置生成、避免与蛇身重叠
- 游戏判定：撞墙/撞自身游戏结束
- 附加功能：游戏计时、R 键重置

## 问题一：边界越界闪退、穿墙 BUG

**【问题】**：蛇移动到窗口边缘不会游戏结束，直接穿墙从对面重生，地图边界失效。

**【排查与原因】**：无边界碰撞判断逻辑，坐标超出地图范围后没有做死亡判定，造成穿墙 BUG。

**【解决方案】**：添加上下左右四周边界判断，蛇头坐标超出地图范围立即触发游戏结束。

**【经验总结】**：游戏边界、碰撞检测是核心安全逻辑，不能默认系统限制，必须手动写判定规则。

---

## 问题二：食物刷新在蛇身上

**【问题】**：食物刷新会随机生成在蛇身体上，导致无法吃掉、游戏卡死。

**【排查与原因】**：食物随机生成时未遍历蛇身坐标校验，随机坐标可能落在蛇身上。

**【解决方案】**：食物生成时循环校验蛇身所有坐标，禁止食物生成在蛇身上，直到生成合法空位坐标。

**【经验总结】**：随机生成类功能必须做合法性校验，否则容易出现重叠、卡死、逻辑失效 BUG。

---

## 问题三：反向按键 BUG 瞬间自撞

**【问题】**：快速连续按方向键会出现反向按键 BUG，导致蛇直接吃到自己瞬间死亡。

**【排查与原因】**：没有禁止 180 度反向操作，蛇前进时允许直接反方向掉头，导致自撞死亡。

**【解决方案】**：增加方向锁机制，禁止蛇直接反向掉头（向上时不能直接向下、向左时不能直接向右），杜绝瞬间自撞。

**【经验总结】**：高速运动类游戏必须限制按键频率和非法方向，否则极易出现玩家误操作与逻辑漏洞。

---

## 问题四：蛇身移动卡顿、速度不稳

**【问题】**：游戏移动刷新频率不稳定，蛇身移动忽快忽慢、画面轻微卡顿闪烁。

**【排查与原因】**：未使用固定帧率刷新，依靠 CPU 空转循环刷新画面，运行速度受设备性能影响，导致卡顿、速度不稳定。

**【解决方案】**：使用 `Sleep()` 固定刷新帧率，统一游戏移动速度，解决设备差异造成的卡顿、变速问题。

**【经验总结】**：游戏帧率必须人工固定，不能依赖 CPU 循环速度，否则运行效果设备差异化严重。

---

## 问题五：按键连续误触发

**【问题】**：按键触发没有冷却，短时间连续输入多个方向指令，导致路径错乱、运动异常。

**【排查与原因】**：使用无延迟按键检测，没有按键缓冲锁，连续按键堆积多条指令，逻辑错乱。

**【解决方案】**：优化按键响应逻辑，每次移动只执行一次最新按键指令，屏蔽多余积压按键，防止操作错乱。

**【经验总结】**：交互类游戏要做好指令过滤、防抖、非法操作拦截，保证游戏逻辑稳定可控。

---

## 问题六：蛇身增长逻辑异常

**【问题】**：蛇身增长逻辑不完善，部分场景吃食物后身体不增长或增长错位。

**【排查与原因】**：蛇身数组更新、坐标后移逻辑不严谨，增长时未正确保留尾部坐标。

**【解决方案】**：重构蛇身移动逻辑：正常移动舍弃尾部，吃食物保留尾部，实现正确增长效果。

**【经验总结】**：动态增长类物体（蛇身、路径、队列）需要严格处理数据结构头尾更新顺序，否则会出现增长异常、错位、卡死。

---

## 问题七：游戏结束后计时继续累加、R 键重置未归零

**【问题】**：游戏结束之后，计时器仍然持续累加；按下 R 键重置游戏，计时不会立刻清零，要等到新一局游戏正式开始运行之后时间才归零。

**【排查与原因】**：计时变量没有绑定游戏运行状态：游戏结束后没有停止计时更新逻辑；R 键重置时只重置蛇、食物数据，没有立刻重置计时变量；计时清零逻辑写在游戏启动分支内，而不是重置操作里。

**【解决方案】**：新增游戏状态标记 `isPlaying`：游戏结束时关闭计时更新；R 键重置的时候直接将计时变量置 0，不等待新一局循环启动；计时更新逻辑包裹在 `isPlaying` 判断内，只有游戏进行中才累加时间。

**【经验总结】**：计时器、分数这类状态变量，要和游戏运行状态绑定；重置操作需要完整重置全部业务变量，不能遗漏计时、分数等附属数据。
